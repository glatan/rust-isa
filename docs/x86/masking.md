# x86 のマスク

AVX-512 と AVX10 は、マスクレジスタ `k0`〜`k7` を使う。クレートはマスクレジスタを直接公開せず、レーン数に応じた符号なし整数で表す。

## 表現

| レーン数 | 型    | ビット |
| -------: | ----- | -----: |
|        8 | `u8`  |      8 |
|       16 | `u16` |     16 |
|       32 | `u32` |     32 |
|       64 | `u64` |     64 |

- ビット `i` がレーン `i` に対応する。
- レーン数より上のビットは 0 にする。呼び出し側の責任とする。
- マスクを返す命令は、レーン数より上のビットを 0 にして返す。
- `k0` を明示マスクとして使わない。マスクなしは `k0` の省略形であり、API ではマスク引数を持たない関数にする。

## 安全境界

- マスク付き命令は `unsafe fn` とする。必要な feature を呼び出し側が有効にする。
- マスクのビット数とレーン数が一致しない場合の動作は定義しない。rustdoc にレーン数を書く。
- マスクを返す比較命令は、真のレーンに対応するビットを 1 にする。

## 型を分けるか

今は生の `u8` / `u16` / `u32` / `u64` を使う。`Mask8` などの newtype は、型 safety が必要になった時点で導入する。公開後に生の整数から newtype へ変えると破壊的変更になるため、1.0 までに必要かどうかを決める。

## 実装

- C の境界では、マスクを `uint8_t` / `uint16_t` / `uint32_t` / `uint64_t` で渡す。
- C の intrinsics は `__mmask8` / `__mmask16` / `__mmask32` / `__mmask64` を受ける。
- マスク付き命令の C 関数は、マスクを値で受け取り、ポインタで値を渡す。
- マスクを返す命令の C 関数は、マスクを戻り値で返す。

## テスト

- マスクの下位ビットだけを使うケースをテストする。
- レーン数より上のビットが無視されることではなく、API が 0 を要求することを rustdoc とテストで確認する。
