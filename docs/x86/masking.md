# x86 のマスク

AVX-512 と AVX10 は、マスクレジスタ `k0`〜`k7` を使う。クレートはマスクレジスタを直接公開せず、レーン数に応じた `MaskN` 型で表す。

## 表現

| レーン数 | 型       | 内部 |
| -------: | -------- | ---- |
|        1 | `Mask1`  | u8   |
|        2 | `Mask2`  | u8   |
|        4 | `Mask4`  | u8   |
|        8 | `Mask8`  | u8   |
|       16 | `Mask16` | u16  |
|       32 | `Mask32` | u32  |
|       64 | `Mask64` | u64  |

- ビット `i` がレーン `i` に対応する。
- `from_bits` はレーン数より上のビットを切り捨てる。
- `from_bits_checked` はレーン数より上のビットがあれば `None` を返す。
- `ALL` はレーン数分の全ビットを立てる。`NONE` は明示的な全偽で、`k0` の省略とは別物である。
- `k0` を明示マスクとして使わない。マスクなしは `k0` の省略形であり、API ではマスク引数を持たない関数にする。

## 適用範囲

次の extension のマスク引数・戻り値は `MaskN` を使う。

- `avx512f`
- `avx512vl`
- `avx512bw`
- `avx512dq`
- `avx512fp16`
- `avx512vbmi2`
- `avx512bitalg`
- `avx10_1`
- `avx10_2`

比較や分類の結果がフラグ（CF / PF / ZF）である命令は、マスクではないため整数のまま返す。`vcomiss`、`vcomisd`、`vcomish`、`vucomish` などが該当する。

## 安全境界

- マスク付き命令は `unsafe fn` とする。必要な feature を呼び出し側が有効にする。
- マスクのビット数とレーン数が一致しない場合の動作は定義しない。rustdoc にレーン数を書く。
- マスクを返す比較命令は、真のレーンに対応するビットを 1 にする。

## 型を分けるか

`Mask1` / `Mask2` / `Mask4` / `Mask8` / `Mask16` / `Mask32` / `Mask64` を使う。レーン数を型で表し、幅の取り違えをコンパイルエラーにする。生の `u8` / `u16` / `u32` / `u64` は公開 API に置かない。AVX2 のベクトルマスクは k-mask ではないため対象外とする。

## 実装

- C の境界では、マスクを `uint8_t` / `uint16_t` / `uint32_t` / `uint64_t` で渡す。
- C の intrinsics は `__mmask8` / `__mmask16` / `__mmask32` / `__mmask64` を受ける。
- マスク付き命令の C 関数は、マスクを値で受け取り、ポインタで値を渡す。
- マスクを返す命令の C 関数は、マスクを戻り値で返す。

## テスト

- マスクの下位ビットだけを使うケースをテストする。
- レーン数より上のビットが無視されることではなく、API が 0 を要求することを rustdoc とテストで確認する。
