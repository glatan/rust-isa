# x86

対象は `x86_64-unknown-linux-gnu` と `i686-unknown-linux-gnu` である。x86_64 を先に扱う。i686 は `sse2` と `avx2` のゼロコスト、`avx512f` と整数（BMI1 / BMI2 / POPCNT / LZCNT / MOVBE）の値テストを確認した。暗号はまだ測っていない。

family は命令の種類に合わせて決める（`simd`、`crypto`、`integer` など）。公開パスは `x86::{family}::{extension}::{instruction}` とする。extension の名前は rustc の feature 名の `.` と `-` を `_` に置き換える（`sse4.1` は `sse4_1`、`avx10.1` は `avx10_1`）。

## 実装方式

- native なので無条件に公開する。任意の feature を要求する命令は `unsafe fn` とする。
- C + clang + LTO を主方式とする。LTO は wasm32 と native のゼロコストに使う。C は `<immintrin.h>` を使う。
- 値は `V128`、`V256`、`V512` をポインタで渡す。C の関数はベクタ型を内部で使い、境界ではポインタを受け取る。
- C は extension ごとに分ける。`-mavx2` のようなファイル全体のフラグを使うか、`__attribute__((target("avx2")))` を関数単位で付ける。
- stable な feature は、呼び出し側のカーネルに `#[target_feature(enable = "...")]` を付ける。ラッパーは `#[inline(always)]` だけにし、`#[target_feature]` を付けない。unstable な feature は付けない。
- `asm!` は補助として使える。`xmm_reg` は `u128` を受け付ける。`ymm_reg` は `avx` を要求し、256-bit の値型を `core::arch` なしでは表せないため、256-bit 以上は C を主とする。

## ソースの分割

extension ごとに内部モジュールの分割軸を決める。SSE2 は操作名で分ける（`arithmetic`、`compare`、`convert`、`bitwise`、`shift`、`shuffle`、`unpack`、`pack`、`movemask`、`moves`、`nontemporal`、`memory`）。値型の定義は `v128` に置く。AVX2 も操作名で分け、AVX-512F は `float` / `gather_scatter` / `integer` / `v512` で分ける。AVX-512F の load/store は `v512` に置き、`gather_scatter` は gather/scatter だけを含む。公開パスには内部モジュール名は出ない。

extension の `mod.rs` が実装本体になることも許容する。AVX-512VL は全 220 命令を実装済みで、各関数が同じ形の wrapper であり、`vp2intersect` だけが追加の AVX-512VP2INTERSECT を要求するため submodule に分けている。行数は分割の基準にしない。追加 feature の境界、操作カテゴリの混在、変更軸の分離が生じたときに operation 別の分割を検討する。AVX10.1 も同じ方針とする。

乱数を生成する `rdrand` と `rdseed` は `integer` に置く。暗号演算ではないため `crypto` には置かない。

## ゼロコスト

x86_64 で条件付きのゼロコストを確認した。条件、Cargo の設定、確認した命令は [リンクとゼロコスト](linking.md) に置く。128-bit は `asm!` と `u128` でも確認した。条件を満たさないビルドでは C への `call` が残る。

## ツールチェーン

- clang、llvm-ar、llvm-objdump。
- clang 23.1.1 で、`-mavx2` と `__attribute__((target("avx2")))` が `vpaddd ymm` を出すことを確認した。
- C の target-features を Rust の部分集合にするため、`-mno-mmx -mno-x87 -mno-popcnt -mno-xsave` を付ける。`cmov` と `cx8` は残ってもインラインされた。
- ホストの x86_64 では、clang の既定 triple は `x86_64-pc-linux-gnu` である。`--target=x86_64-unknown-linux-gnu` を明示すると triple の不一致警告が出る。ホストでは `--target` を省く。
- ゼロコストの確認は rustc 1.99.1、clang/lld 23.1.1 で行った。クロス LTO は LLVM のバージョンに依存する。テストした組み合わせをここに追記する。
- AMX は `-mamx-tile -mamx-bf16` で C がコンパイルでき、`ldtilecfg`、`tileloadd`、`tilestored`、`tilerelease` を出した。タイル状態の guard が必要である。

## 実装の順序

1. `sse2`（x86_64 の既定）
2. `ssse3`、`sse4.1`、`sse4.2`
3. `avx`、`avx2`、`fma`
4. `avx512f` とその拡張
5. `aes`、`sha`、`pclmulqdq`
6. `bmi1`、`bmi2`、`popcnt` など

## 対象外

- AVX10.1 / AVX10.2 の組み込み丸め制御と、AVX10.1 のベクトル長選択。丸めモードを引数に取る API を持たないため、命令 API にしない。
- `kl` / `widekl`、`rtm`。`kl` は状態、`rtm` は制御命令のため、値 API にしない。

## 未対応

- i686 の暗号の値テスト。
- AMX の `amx-avx512` と `amx-movrs`。`amx-tile` の load / store / matrix multiply は実装済みである。
- AVX10.1 / AVX10.2 で `#[target_feature]` を使えない制約の再確認。
- shuffle / compress のうち、intrinsics が往復を残す命令の個別確認。
- 追加した SSE3 以降の命令のゼロコスト確認。現在の zero-cost は
  [リンクとゼロコスト](linking.md) に書いた命令だけである。
